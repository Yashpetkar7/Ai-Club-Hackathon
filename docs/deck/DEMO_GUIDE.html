Before going on stage

  1. Use Node 22.19+, install locked dependencies with npm ci, run npm run verify and npm run e2e.
  2. Start with npm start; open 127.0.0.1:4173. In a second terminal run npm run demo:check. Inspect its timestamped report.
  3. Run the complete browser journey and open the downloaded citation file. Test a 375px viewport and keyboard controls. Preload the optional model if you plan to demonstrate paraphrase support.
  4. Keep a previously prepared project as a clearly announced backup. Save a genuinely recorded Lab result with its SAMPLE label. Use a hotspot if needed; a free key does not guarantee availability.
  5. Use public research text. Confirm optional provider terms and assessment permissions before sending task input. Do not place keys in slides, source code or chat.

Inputs and narration

Research question:
Does working from home improve employee productivity?

Known source identifier:
10.1093/qje/qju032

Claim using the source’s reported number:
Home working led to a 13% performance increase.

DELIBERATE TEST MUTATION, NOT A RESEARCH FINDING:
Home working led to a 31% performance increase.

Search counts, ordering, availability and labels can change. Confirmed means identity checks passed. Verified means the implemented source-support checks passed; neither establishes scientific truth.

Answers worth learning

What is the edge? One inspectable workflow combines research decisions and learning from actual source text. Competitive superiority is unproven.

Can it be manipulated? Some edits can be detected; browser data and rebuilt logs are not tamper-proof. Permission levels are declarations.

Where is AI? Optional fixed tasks through Groq/Gemini and optional on-device support inference. Registry identity verdicts come from code.

What is proven today? Consult the current validation record. Do not reuse historical totals as a new run.
