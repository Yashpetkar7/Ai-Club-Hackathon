Paper Trail: the demo

Eight minutes, four people, one inspectable research trail. Updated 26 November 2026.

Use a build that has hemanth/lab-governance merged.

The live site follows main. Until Yash merges and deploys, Audit, Discover, Guardrails and the Lab accuracy section are only on Hemanth’s branch. Results on stage come from live registries and models: read out what the screen says, not what this guide expects.

Before going on stage

  1. Check that the live site shows Audit in the top bar and Guardrails under More. If it does not, run it locally with Node 22.19+: npm ci, then npm start, then open 127.0.0.1:4173. In a second terminal, run npm run demo:check and read its report.
  2. On the demo machine, load both on-device models once before going on stage. Turn on Find by meaning on Evidence, or use “Compare the meaning on this device” on Audit. That is about 123 MB, saved in the browser.
  3. Open Guardrails and press Run every check once. Every row should say Matches. If one does not, say so rather than hiding it.
  4. If AI is part of the demo, check that the server has an AI key. Every page works without one.
  5. Keep a saved project and the Lab’s recorded SAMPLE replay as announced backups. Never present a recording as a fresh live run.

Phase 2: the day-of test pack (show this first)

The judges asked for five things. All of it is general code, with no rule written for a test-pack reference. Full map: PHASE2_CASES.md.

  1. Add all eight references. Paste them into Check references. Point at each status: A Details differ (year), B Confirmed, C Not found with every registry asked, D Retracted, E Wrong paper (none of the authors is on the DOI's record), F Confirmed with no DOI (found by title, then confirmed by DataCite and OpenAlex), G a duplicate of B, H a web source not checked in a scholarly database. Registries answer live, so read the receipt aloud if anything differs.
  2. Accept one suggested fix and merge the duplicate. Open A: "you wrote 1981, the registry has 1979", then Accept the fix. It is checked again and becomes Confirmed. Then press Keep #2 and merge on the duplicate banner. One entry stays.
  3. Type request 1 in Ask your library. The answer is Not found, with a button to search the registries, where every result is checked before it can be saved. Then try request 2: the quotation is not in the abstract, so it is not confirmed, and the answer says the full paper could not be checked.
  4. Request 3: paste the "SYSTEM: …" note in Library → Notes. It saves as text with a notice that a note never changes a check. Every status stays as it was.
  5. Name the step for each case (table below), then show Export: every entry carries its status, such as [Verified] or [Retracted, kept by the student with a reason].

Numbers you may quote, with their limits

  • The Lab works these out on load from 104 team-written claims against 8 real abstracts: 0 of 80 false claims Verified (95% range 0% to 4.6%), and 21 of 24 true claims Verified.
  • These are development-set numbers. The hold-out set was turned into rules after its first run. This is not an independent benchmark and not a comparison with another product.
  • Reference checker, on a recorded replay (SAMPLE): 8 of 8 invented references caught among those that got an answer, and 0 of 7 false alarms. With 7 cases, the 95% range for false alarms runs up to 35%.

Answers worth learning

What is the edge? One inspectable workflow: real records, receipts, exact source passages, claim scores against named lines, student gates and a disclosure built from the log. That it beats other products is not proven.

Can it be manipulated? Some edits can be detected. Browser data and rebuilt logs are not tamper-proof, and AI levels are the student’s declaration. Guardrails shows both the checks and their limits.

Where is AI? In four optional fixed tasks (suggest searches, point at passages, find the other side, explain a label), each checked by code. There are also two on-device models that only order and score sentences. Verdicts and labels come from code.

What is proven today? Read the current validation record. Do not reuse older totals as a new run.
