### A fair way to test the proposed edge

Agree the tasks, reference set and pass/failure definitions before measuring. Use equivalent input, source access, product mode and human assistance; record versions and dates. Compare completed task outcomes, correction effort, evidence coverage, false confirmations, false alarms and recovery separately. Publish unavailable and unrun cases instead of removing them from the denominator. Timing requires an actual controlled run. Different unit-test counts, review stars and marketing statements are not a comparative reliability measurement.

Keep mutations inside the clearly labelled Lab. Do not circulate invented citations as research sources, alter the corpus after seeing outcomes, or claim a result from a competitor that nobody actually tested. Complete our own journey first, then evaluate whether it helps a student more reliably.

## A focused extension after the required work

**Proposed: a compact evidence receipt carried through to export.** Check already exposes structured comparison evidence; the new HTML report summarises sources, keys, reasons and local history. Connect those elements so a student can see the submitted reference, returned fields, consulted registries, unavailable stages, checked time and final decision in one place. Keep the source warning and override reason visible in the actual citation handoff.

Acceptance is a receipt that stays accurate when enrichment fails, a source has no matching record, a result is a labelled replay, or the student uses an allowed exception. It must distinguish bibliographic identity, claim support and scientific validity. **Hemanth** can present this within the Lab and governance pages; shared reusable components and citation files belong to **Yash/Siddal**. This is a workflow proposal, not a novelty claim. [Competitor evidence](RESEARCH_AUDIT.md#competitor-features-keep-the-comparison-specific).
