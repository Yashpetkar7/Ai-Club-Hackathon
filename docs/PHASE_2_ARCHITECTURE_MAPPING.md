# Phase 2 architecture mapping

Every Phase 2 requirement lands on an agent or component that already existed in Phase 1. The agent names are the ones in `src/policy/policy.ts` (`AGENTS`). **No new agent was created.** The research assistant is plain code that chains the existing **Scout** (registry search) and **Checker** (`checkReference`), so it holds no key and cannot set a status.

|---|---|---|---|---|
| Six statuses with fixed precedence | **Checker** (`src/core/verify/verdict.ts`) | `src/core/verify/status.ts` maps the Checker's verdicts onto VERIFIED, NEEDS FIX, MISMATCH, RETRACTED, NOT FOUND and NOT CHECKED. It also writes the export tag. Only the Checker's verdict can produce a status. | `statusOf`, `statusTag` | `tests/unit/phase2.test.ts` ("status precedence") |

Every lookup, its outcome and its time are kept in `trace` and shown in the receipt. | `verdict.ts`, `registries/index.ts` | Live: reference C. Unit test: outage |

## What stayed the same
The stack (React, Vite, the small Node server), the three-key rule, the fixed-task AI gateway with server-side level checks, local-first storage with encrypted copies on the server, and every Phase 1 page. Secrets stay server-side: the browser never sees an API key.

## Database changes
The library uses IndexedDB (Dexie). The new `Source` fields `original`, `fixes` and `retractionAcknowledged` are optional and unindexed, so **no schema version bump or migration is needed**. Existing libraries open unchanged. Each decision is a single atomic `update` of one source, followed by a log event.
